## Anti-Patterns Verdict

**Pass (mostly clean).** Not cream/purple AI-slop. Identity is cool clinical teal + stone wash with Geist. Detector returned no hits. Remaining tells: demo multi-role nav (6 options), admin metric tiles edge toward hero-metric, uppercase status chips on appointment cards.

## Priority Issues

1. **[P1] Demo role nav exposes all personas** — Patients see Reception/Doctor/Admin. Split auth-gated shells.
2. **[P1] Raw status/type strings** — `Booked`, `Present`, etc. not i18n'd; breaks Arabic UX.
3. **[P1] Destructive actions without confirm** — Restrict booking / suspend clinic.
4. **[P2] Clinic ID as free-text GUID** — High friction; needs picker/search after auth.
5. **[P2] Empty/help states still thin** — Bookings/reception empty copy doesn't teach next step.

## Persona Red Flags

- **Patient (mobile, Arabic):** Role nav noise; GUID clinic ID; English status chips.
- **Receptionist (busy desk):** Touch targets improved; still no confirm on restrict.
- **Doctor:** Visit flow clearer with labeled Rx fields; session status still English enum.

## Strengths

- Skip link, RTL `dir`/`lang`, i18next coverage for chrome copy
- Shared tokens + `cq-*` primitives; semantic wait/go instruction colors
- Queue number + instruction as visual peak on patient cards
